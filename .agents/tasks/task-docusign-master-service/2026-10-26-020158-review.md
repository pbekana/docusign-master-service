# DocuSign Master Service — Go Implementation

This PR delivers the complete Go implementation of a DocuSign data-extraction service: JWT OAuth, a paginated envelope/recipient/document/template pipeline, PostgreSQL persistence with migrations, MinIO Parquet upload, HMAC request signing middleware, and a 16-endpoint Chi router. All five feature tracks completed. `go build ./...` and `go test ./...` both pass cleanly with no live credentials required — tests use mock HTTP servers throughout.

Watch for: (1) `output_format` and `upload_to_minio` columns are on the `Job` model but absent from migration 001, so `CREATE` queries don't persist them and `GetByID` won't restore them — **confirmed schema gap**. (2) `MarkCrashed` builds its `INTERVAL` clause via `fmt.Sprintf` with an unvalidated integer — the value comes from config, not user input, so the risk is low but the pattern is still worth fixing. (3) `/api/stats` is registered outside the HMAC group but the HMAC middleware also skips it with a `HasPrefix` check — this double-skip is redundant and slightly confusing but harmless.

**Verdict**: NEEDS_CHANGES

---

## High-level view

The JWT auth client correctly implements the DocuSign JWT Bearer flow: `aud` is hostname-only, `grant_type` is `urn:ietf:params:oauth:grant-type:jwt-bearer`, tokens are cached until 5 minutes before expiry, and no secret material is logged.

The resilience layer treats 429 as a separate outer loop around `DoWithRetry`, so rate-limit responses never consume a retry attempt. When `Retry-After` exceeds `maxWaitSecs`, a typed `RateLimitExceededError` is returned rather than sleeping — callers can detect this and persist resumable state.

Both public routes (`/api/health`, `/api/stats`) are registered outside the HMAC-protected Chi group and the middleware also skips them explicitly — the double-skip is a redundancy worth resolving (see Issues).

The `jobs` table migration is missing two columns that the `Job` model and repository expect: `output_format` and `upload_to_minio`. In production every job will have `OutputFormat=""` and `UploadToMinio=false` after any database round-trip, silently discarding the caller's requested values.

The DocuSign client package (`internal/docusign/`) has no test file. URL-construction bugs in any of the four API methods would pass the service-level tests and only fail against a live account.

<summary>Issues (3)</summary>

1. **`output_format` / `upload_to_minio` missing from migration** — Migration 001 does not define these columns. Add `output_format TEXT NOT NULL DEFAULT 'parquet'` and `upload_to_minio BOOLEAN NOT NULL DEFAULT FALSE` to the `CREATE TABLE jobs` statement, and update the `Create` INSERT and `GetByID`/`List` SELECT queries to read and write them.

2. **`MarkCrashed` SQL injection via `fmt.Sprintf`** — The crash-timeout interval is assembled with `fmt.Sprintf("... INTERVAL '%d minutes'", crashTimeoutMinutes)` rather than a parameterized query. `crashTimeoutMinutes` is an `int` from config so there is no real injection vector, but the pattern is fragile. Replace with `NOW() - ($1 * INTERVAL '1 minute')` or `NOW() - make_interval(mins => $1)` using a bound parameter.

3. **No tests for `internal/docusign`** — The DocuSign client package has no test file. JWT auth is untestable without credentials, but `ListEnvelopes`, `GetRecipients`, `GetDocuments`, and `ListTemplates` all use `doRequest` against a URL and could be tested with an `httptest.Server`. The `service_test.go` adapter covers the pipeline end-to-end, but a URL-construction bug in any of those four methods would not be caught until a live call.

### Schema gap: `output_format` and `upload_to_minio` not persisted

Migration 001 creates the `jobs` table without `output_format` or `upload_to_minio` columns. The `JobRepository.Create` query inserts nine columns and reads them back via `RETURNING` — neither field is included. `GetByID` and `List` have the same gap in their `SELECT` lists. The `Job` struct carries both fields and the `jobServiceAdapter.runJob` test path reads `job.UploadToMinio` to decide whether to skip the MinIO stage. In production, every job will have `output_format = ""` and `upload_to_minio = false` after `Create` returns, regardless of what the caller requested. This is a confirmed bug: the schema and the query layer are inconsistent.

### `MarkCrashed` interval interpolation

```go
tag, err := r.pool.Exec(ctx, fmt.Sprintf(`
    UPDATE jobs SET status='CRASHED', updated_at=NOW()
    WHERE status IN (...)
      AND last_heartbeat_at < NOW() - INTERVAL '%d minutes'
`, crashTimeoutMinutes))
```

`crashTimeoutMinutes` is an `int` obtained from `config.CrashTimeoutMinutes`, which is loaded from an environment variable with a default of 10. There is no path for untrusted user input to reach this value, so in practice there is no exploitable injection. The pattern is still worth correcting: PostgreSQL supports `NOW() - ($1 * INTERVAL '1 minute')` or `make_interval(mins => $1)`, both of which bind the value as a parameter.

### DocuSign client package has no tests

`internal/docusign/` exports `ListEnvelopes`, `GetRecipients`, `GetDocuments`, and `ListTemplates` — four functions that construct API URLs and decode JSON responses. None of them have a test. The pipeline-level `service_test.go` exercises these paths indirectly, but it uses a correctly wired mock server that already matches the expected URL patterns. A typo in a URL template (e.g., `envelopes` vs `envelope`) would pass the service test and only fail against a real account.

### `/api/stats` public-access logic is redundant

`/api/stats` is registered on the root Chi router before the HMAC group, meaning requests to it never enter the HMAC middleware at all. The middleware also contains an explicit `strings.HasPrefix(r.URL.Path, "/api/stats")` skip. The double-skip is harmless but creates a maintenance hazard: a future developer editing only the middleware skip rule would not know the route is also outside the group. The middleware comment and skip condition should reference only `/api/health`, or the two should be brought into a single source of truth.
